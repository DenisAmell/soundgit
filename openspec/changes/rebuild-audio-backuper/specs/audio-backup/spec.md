## ADDED Requirements

### Requirement: Привязка папки к облаку

Система SHALL позволять связать локальную папку с папкой в облаке одного из подключённых аккаунтов и вести несколько таких привязок независимо друг от друга.

#### Scenario: Два проекта с разными папками

- **WHEN** в двух проектах DAW заданы разные локальные папки
- **THEN** файлы из каждой папки попадают в свою папку в облаке и не смешиваются

#### Scenario: Вложенные папки

- **WHEN** у привязки включены вложенные папки и файл появляется в подпапке
- **THEN** файл обрабатывается так же, как файл в корне привязки

### Requirement: Копирование новых файлов

Система SHALL ставить в очередь загрузки каждый новый аудиофайл в привязанной папке после того, как его запись завершена.

#### Scenario: Записан новый рендер

- **WHEN** в папке появился аудиофайл, и его размер и время изменения не менялись 2 секунды
- **THEN** файл поставлен в очередь загрузки

#### Scenario: Файл ещё пишется

- **WHEN** DAW продолжает дописывать файл
- **THEN** загрузка не начинается, пока запись не завершится

#### Scenario: Служебный файл

- **WHEN** в папке появился скрытый файл, временный файл или файл с неаудиорасширением
- **THEN** файл не загружается

### Requirement: Копирование изменённых файлов

Система SHALL загружать файл заново, когда его содержимое изменилось после предыдущей загрузки, и не загружать, когда содержимое прежнее.

#### Scenario: Рендер перезаписан под тем же именем

- **WHEN** уже загруженный файл перезаписан с другим содержимым
- **THEN** новая версия поставлена в очередь загрузки

#### Scenario: Изменилось только время файла

- **WHEN** у загруженного файла изменилось время изменения, а содержимое осталось прежним
- **THEN** файл не загружается повторно

### Requirement: Догон после простоя

Система SHALL при запуске находить файлы, появившиеся или изменившиеся в привязанной папке, пока она не работала, и ставить их в очередь.

#### Scenario: Рендер сделан при выключенном помощнике

- **WHEN** файл появился в папке, пока помощник не был запущен, и затем помощник запускается с этой привязкой
- **THEN** файл поставлен в очередь загрузки без действий пользователя

### Requirement: Файлы, существовавшие до привязки

Система SHALL не загружать файлы, которые уже лежали в папке в момент создания привязки, пока пользователь явно этого не запросит.

#### Scenario: Привязана папка со старыми рендерами

- **WHEN** создана привязка к папке, в которой уже есть аудиофайлы
- **THEN** эти файлы не загружаются
- **AND** файл, появившийся после создания привязки, загружается

#### Scenario: Загрузить имеющиеся

- **WHEN** пользователь выбирает загрузку уже имеющихся файлов
- **THEN** все аудиофайлы папки, которых нет в облаке, поставлены в очередь

### Requirement: Расположение в облаке

Система SHALL размещать файл в облаке по пути, повторяющему его относительный путь внутри привязанной папки, и сохранять имя файла.

#### Scenario: Файл в подпапке

- **WHEN** загружается файл `Stems/Drums/kick.wav` из привязанной папки
- **THEN** в папке привязки в облаке он лежит по пути `Stems/Drums/kick.wav`

#### Scenario: Имя со специальными символами

- **WHEN** загружается файл с именем `Untitled_1#01 & микс+2.wav`
- **THEN** файл в облаке имеет то же имя

#### Scenario: Одинаковые имена в разных подпапках

- **WHEN** в двух подпапках лежат файлы с одинаковым именем
- **THEN** в облаке сохранены оба файла, каждый в своей подпапке

### Requirement: Сохранение прежних версий

Система SHALL по умолчанию сохранять в облаке прежнюю версию файла при загрузке изменённой, а при выбранной перезаписи — заменять её.

#### Scenario: Прежняя версия сохраняется

- **WHEN** загружается изменённый файл, а у привязки включено хранение версий
- **THEN** в облаке под исходным именем лежит новая версия
- **AND** прежняя версия лежит рядом под именем с датой и временем её загрузки

#### Scenario: Перезапись

- **WHEN** загружается изменённый файл, а у привязки выбрана перезапись
- **THEN** в облаке под исходным именем лежит только новая версия

#### Scenario: Чужой файл по тому же пути

- **WHEN** в облаке по целевому пути лежит файл, загруженный не этой системой
- **THEN** он не изменяется, а загружаемый файл получает отличающееся имя

### Requirement: Целостность загруженного файла

Система MUST после загрузки убедиться, что файл в облаке совпадает с локальным по размеру и контрольной сумме, и не считать файл загруженным при расхождении.

#### Scenario: Успешная загрузка

- **WHEN** загрузка завершена и облако сообщает тот же размер и ту же контрольную сумму
- **THEN** файл отмечен как загруженный

#### Scenario: Расхождение

- **WHEN** размер или контрольная сумма в облаке не совпадают с локальными
- **THEN** файл не отмечен как загруженный и загрузка повторяется

### Requirement: Очередь переживает перезапуск

Система SHALL сохранять очередь загрузки и сведения о загруженных файлах между запусками.

#### Scenario: Перезагрузка посреди загрузки

- **WHEN** помощник завершён во время загрузки файла и запущен снова
- **THEN** этот файл и остальные файлы очереди загружаются без действий пользователя

#### Scenario: Уже загруженное не загружается повторно

- **WHEN** помощник перезапущен, а файлы в папке не менялись
- **THEN** ни один ранее загруженный файл не загружается заново

### Requirement: Повторы и классы ошибок

Система SHALL повторять загрузку после временной ошибки с нарастающей паузой без ограничения числа попыток и MUST NOT исключать файл из очереди без записи, видимой пользователю.

#### Scenario: Нет сети

- **WHEN** сеть недоступна час, а затем появляется
- **THEN** файлы, ожидавшие в очереди, загружаются

#### Scenario: Закончилось место в облаке

- **WHEN** облако отказывает из-за нехватки места
- **THEN** загрузки этого аккаунта приостановлены, очередь сохранена, пользователю показана причина

#### Scenario: Файл удалён до загрузки

- **WHEN** файл из очереди удалён с диска до начала загрузки
- **THEN** он снят с очереди с записью в журнале, остальные файлы загружаются

#### Scenario: Имя не принято облаком

- **WHEN** облако отказывается принять один файл из-за его имени
- **THEN** этот файл помечен как неудавшийся с причиной, остальные файлы загружаются

### Requirement: Пауза

Система SHALL по команде пользователя приостанавливать и возобновлять загрузки, не теряя очередь.

#### Scenario: Пауза и возобновление

- **WHEN** загрузки приостановлены, в папке появляются новые файлы, затем пауза снята
- **THEN** все появившиеся файлы загружаются

### Requirement: Большие файлы

Система SHALL загружать файлы размером в несколько гигабайт, не ограничивая общее время загрузки и не занимая память пропорционально размеру файла.

#### Scenario: Двухгигабайтный файл на медленном канале

- **WHEN** загружается файл размером 2 ГБ и загрузка длится дольше получаса
- **THEN** загрузка завершается успешно, а потребление памяти помощником не растёт с размером файла

## REMOVED Requirements

### Requirement: Обнаружение новых аудиофайлов

**Reason**: Заменено требованиями «Копирование новых файлов», «Копирование изменённых файлов» и «Догон после простоя»: отслеживание только появления файлов и пропуск существовавших до запуска не соответствуют продукту.
**Migration**: Поведение для новых файлов сохраняется; дополнительно начинают копироваться изменённые файлы и файлы, появившиеся при выключенном помощнике.

### Requirement: Загрузка в облако с повторами

**Reason**: Заменено требованиями «Расположение в облаке», «Сохранение прежних версий», «Повторы и классы ошибок»: раскладка по дате загрузки теряла структуру папок и затирала одноимённые файлы, а файл после пяти неудач молча выбрасывался.
**Migration**: Новые загрузки идут в папку привязки с сохранением структуры; файлы, загруженные прототипом в папки по датам, остаются на месте и не переносятся.

### Requirement: Управление через локальный API

**Reason**: Локальный API заменён защищённым (возможность `backup-helper`); прежние адреса и фиксированный порт 47291 не поддерживаются.
**Migration**: Сторонних клиентов у API не было; плагин обновляется вместе с помощником.

### Requirement: Сохранение настроек

**Reason**: Одна папка на всю машину в файле `~/.audio-backuper.json` заменена привязками, которые хранит помощник, и сохранением привязки в проекте DAW (возможности `backup-helper`, `backup-plugin`).
**Migration**: Старый файл не читается; папку нужно выбрать заново в окне плагина, в облако — войти заново. Файл можно удалить.

### Requirement: Управление сервисом из плагина без нагрузки на звук

**Reason**: Перенесено в возможность `backup-plugin` с более строгими требованиями: без блокировок интерфейса DAW и без запуска процессов при подготовке звука.
**Migration**: Не требуется.
