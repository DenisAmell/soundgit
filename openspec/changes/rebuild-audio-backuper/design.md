## Context

Разбор прототипа — `openspec/audio-backuper.md`. Проверено на машине автора: плагин собирается и проходит `auval`; установлены Logic Pro 11.2 и Reaper 7.86; Ableton Live нет; сертификатов подписи кода нет (плагин подписан ad-hoc).

Автор выбрал подход: **Go-помощник внутри бандла плагина** (2026-11-15). Рассматривались: Node.js с упаковкой рантайма (плюс 50–90 МБ, та же архитектура) и вся логика внутри плагина (загрузка обрывается при закрытии DAW, сбой роняет DAW, каждый экземпляр работает сам по себе).

**Допущение [решение]:** плагин ставят и другие люди, не только автор. Отсюда вход через браузер и системное хранилище секретов. Автор допущение не оспорил.

## Goals / Non-Goals

**Goals:**

- Рендер, появившийся или изменившийся в папке, оказывается в облаке без действий пользователя и без потерь: ни при закрытии DAW, ни при обрыве сети, ни при перезагрузке.
- Плагин не слышно и не видно: звук проходит без изменений, интерфейс DAW не подтормаживает.
- На чистой машине достаточно поставить плагин.
- Чужая программа или веб-страница не может получить доступ к облаку пользователя через помощника.
- Одинаковое поведение для Яндекс Диска и Google Drive.

**Non-Goals:**

- Установщики, подпись, нотаризация, автообновление.
- Восстановление из облака, двусторонняя синхронизация, удаление в облаке вслед за удалением на диске.
- Дедупликация и чанки (это SoundGit).
- Ограничение скорости, расписание, работа по сети между машинами.

## Decisions

### D1. Где живёт код

Помощник — второй исполняемый файл существующего Go-модуля `core/`: `core/cmd/audio-backuper-helper`, пакеты `core/internal/backuper/{api,watch,state,queue,cloud,auth,lifecycle}`.
**Причина:** общий код с ядром (BLAKE3, атомарная запись файлов), одна сборка и один CI. Продукт отдельный, модуль общий.
**Альтернатива:** отдельный модуль `backuper/` — отвергнуто: пакеты `internal` между модулями не разделить, пришлось бы дублировать.

### D2. Жизненный цикл помощника

- Каталог данных пользователя: macOS `~/Library/Application Support/AudioBackuper/`, Windows `%APPDATA%\AudioBackuper\`, Linux `$XDG_CONFIG_HOME/audio-backuper/`. Права — только владельцу.
- При старте помощник берёт блокировку в каталоге данных (второй экземпляр завершается сразу), занимает случайный свободный порт на `127.0.0.1`, генерирует случайный секрет и атомарно пишет `helper.json` `{port, secret, pid, version}` с правами `0600`.
- **[решение при реализации]** Плагин начинает работать с помощником при первом настоящем использовании — подготовке звука, открытии окна или загрузке состояния проекта, — а не при создании экземпляра. Иначе каждое сканирование плагинов в DAW запускало бы помощника.
- Плагин читает `helper.json` и проверяет связь. Нет ответа — запускает помощника из своего бандла отвязанным от процесса DAW (своя сессия; закрытие DAW его не завершает) и ждёт появления файла.
- Клиенты раз в несколько секунд опрашивают состояние — это же сигнал «я жив». Помощник завершается сам, когда клиентов нет дольше 60 с **и** очередь пуста.
- Плагин новее работающего помощника → просит его завершиться (очередь на диске) и запускает свой.

**Причина случайного порта:** фиксированный порт конфликтует и предсказуем для атак.
**Риск:** хост может запрещать плагину запуск процессов (изолированный процесс размещения AU в Logic). Проверяется первой же задачей в Logic; запасной вариант — агент пользователя, который ставит установщик (`launchd` / автозапуск), а плагин только подключается. Протокол от этого не меняется.

### D3. Защита локального API

HTTP + JSON на `127.0.0.1`. Каждый запрос обязан нести секрет из `helper.json` в заголовке `Authorization: Bearer`; сравнение за постоянное время. Запрос с заголовком `Origin` отклоняется; заголовки CORS не выставляются; `Host` должен быть `127.0.0.1:<порт>` (защита от DNS rebinding). Ни один ответ не содержит токенов облака и секрета. Тело запроса ограничено по размеру.
**Причина:** в прототипе веб-страница могла прочитать токен; это главный дефект безопасности.

### D4. Модель: аккаунт и привязка папки

- **Аккаунт** — вход в одно облако (`yandex` или `gdrive`), идентификатор, отображаемое имя.
- **Привязка (watch)** — `{id, локальная папка, аккаунт, папка в облаке, вложенные папки: да/нет, прежние версии: хранить/перезаписывать}`. Привязок может быть много.
- Экземпляр плагина хранит в проекте DAW идентификатор привязки и её параметры без секретов и при загрузке проекта просит помощника «обеспечить привязку» (создать или подтвердить). Помощник хранит привязки и состояние у себя, чтобы догружать и догонять без плагина.
- Привязка активна (за папкой следят), пока жив хотя бы один клиент, который её обеспечил, и пока по ней есть очередь.

### D5. Обнаружение и состояние файлов

- **[решение при реализации] Папка опрашивается, события файловой системы не используются.** Раз в 2 секунды (чаще, пока файл дописывается) каталог обходится целиком. Причина: файл всё равно ждёт 2 секунды неизменности, так что события не ускоряют загрузку; опрос одинаково работает на всех ОС и на сетевых дисках и не требует зависимости. Обход большой папки делается реже, чтобы занимать не больше трети процента времени.
- Кандидат — файл с аудиорасширением (список прототипа), не скрытый и не служебный (`.reapeaks`, `.asd`, `.pkf`, временные файлы).
- Файл считается записанным, когда размер и время изменения не менялись 2 с и файл открывается на чтение.
- Состояние привязки: путь → `{размер, время изменения, BLAKE3 содержимого, имя и идентификатор в облаке, когда загружен}`. Совпали размер и время — файл не читается. Иначе считается контрольная сумма: совпала — обновляется только время; не совпала — файл в очередь.
- **[решение] Файлы, уже лежавшие в папке при создании привязки, записываются как «известные» и не загружаются**; загрузить их — отдельное действие в окне. Причина: папка рендеров может содержать гигабайты старого; неожиданная выгрузка всего — плохой первый опыт.
- Удаление и переименование локального файла на облако не влияет (non-goal), запись состояния о нём убирается.

### D6. Расположение и версии в облаке

- Путь в облаке: `<папка привязки>/<относительный путь файла>`; структура вложенных папок сохраняется.
- **[решение] Прежняя версия изменённого файла по умолчанию сохраняется**: перед загрузкой новой прежний файл в облаке переименовывается в `<имя> (ГГГГ-ММ-ДД ЧЧ-ММ-СС).<расширение>` по времени его загрузки. Причина: перезаписать баунс под тем же именем — обычное дело, а потерять прежний микс — именно то, от чего защищает резервная копия. Настройка привязки позволяет перезаписывать.
- Если в облаке по целевому пути уже лежит файл, о котором помощник не знает (загружен не им), он не затирается: новый получает суффикс.
- Имена кодируются для URL целиком; недопустимые для облака символы заменяются с записью в журнал.

### D7. Облака за общим интерфейсом

`Provider`: сведения об аккаунте и квоте, создание цепочки папок, потоковая загрузка с отчётом о ходе, переименование, проверка существования и контрольной суммы.

| | Яндекс Диск | Google Drive |
|---|---|---|
| API | REST `cloud-api.yandex.net/v1/disk` | Drive v3 |
| Права **[решение]** | `cloud_api:disk.app_folder` — только папка приложения (`app:/`), и `cloud_api:disk.info` — имя аккаунта и свободное место | `drive.file` — только файлы, созданные приложением |
| Вход | Код устройства: помощник получает код, открывает страницу подтверждения в браузере, опрашивает выдачу токена | Код авторизации с PKCE, перенаправление на временный адрес `127.0.0.1:<порт>` помощника |
| Загрузка | Запрос адреса загрузки, затем `PUT` потоком | Возобновляемая загрузка, докачка с места обрыва |
| Адресация | Пути | Идентификаторы; помощник кэширует путь → идентификатор папки |
| Проверка | Размер и `md5` из метаданных | Размер и `md5Checksum` |

**Причина минимальных прав:** приложению не нужен весь диск пользователя; для Google это ещё и освобождает от проверки приложения как «чувствительного».
**Следствие:** пользователь выбирает не произвольное место на диске, а папку внутри области приложения.
Контрольная сумма `md5` считается на лету при загрузке вместе с BLAKE3.

Идентификаторы клиентов OAuth задаются при сборке (не в репозитории; образец — `oauth.example.json`). Без них облако показывается в окне как «не настроено в этой сборке». Для разработки остаётся ручной ввод токена Яндекса.

### D8. Хранение доступа

Токены обновления и доступа — в системном хранилище секретов (Keychain, Credential Manager, Secret Service), ключ — идентификатор аккаунта. В файлах состояния, проекте DAW, журнале и ответах API их нет. Если хранилище недоступно (Linux без сервиса секретов) — файл с правами `0600` и предупреждение в окне.
Доступ обновляется заранее; отказ в обновлении переводит аккаунт в состояние «нужен вход», его загрузки приостанавливаются, очередь сохраняется.

### D9. Очередь

- Состояние и очередь — JSON-файлы в каталоге данных, перезапись атомарная. **Причина:** объёмы малы (тысячи записей), формат отлаживается глазами. База данных — если понадобится.
- Одновременно две загрузки; чтение файла потоком, без общего таймаута на запрос — только таймаут простоя соединения.
- Перед загрузкой файл проверяется заново: изменился с момента постановки — ждём стабильности снова; исчез — запись снимается с пометкой в журнале.
- Классы ошибок: **временная** (сеть, 5xx, 429) — повтор с нарастающей паузой до 5 минут, без ограничения числа; **нужен вход** — пауза аккаунта; **нет места** — пауза аккаунта до изменения квоты или повтора вручную; **постоянная по файлу** (имя не принято облаком) — файл помечается, остальные идут дальше. Файл никогда не выбрасывается молча.
- После загрузки сверяются размер и контрольная сумма из метаданных облака; несовпадение — повтор.

### D10. Плагин

- Вся связь с помощником — в собственном фоновом потоке плагина; поток интерфейса и аудиопоток не делают ни сетевых вызовов, ни запуска процессов, ни ожиданий. Интерфейс получает снимок состояния через асинхронное уведомление.
- Подключение идёт в фоновом потоке (когда он стартует — см. D2); `prepareToPlay` только запускает этот поток и ничего не ждёт. Удаление экземпляра помощника не останавливает и дожидается лишь завершения текущего запроса к этой же машине.
- Запросы строятся средствами JSON библиотеки, без склейки строк.
- `processBlock` ничего не делает; раскладки каналов: любая, где вход равен выходу; задержка и хвост — ноль.
- Состояние в проекте: идентификатор и параметры привязки. Секретов нет.
- Окно — три состояния: **подключение облака** (выбор облака, «Войти», ожидание браузера), **настройка папки** (локальная папка, папка в облаке, вложенные папки, версии, «загрузить уже имеющиеся»), **работа** (аккаунт и свободное место, счётчик очереди, текущий файл с ходом, последние загруженные, ошибки с действием, пауза, «повторить»).
- Подсказка локальной папки по хосту: Logic → `~/Music/Logic/Bounces`; иначе — последняя выбранная.
- Помощник лежит в бандле: macOS `Contents/Resources/audio-backuper-helper` (универсальный arm64 + x86_64), Windows `Contents/Resources/audio-backuper-helper.exe`. CMake собирает его и подписывает бандл после копирования.
- Форматы: AU и VST3 на macOS, VST3 на Windows; Standalone остаётся для разработки.

### D11. Проверка

- Помощник: модульные тесты; облака — против поддельных HTTP-серверов, воспроизводящих ответы API, включая обрывы и ошибки; сквозной тест «папка → поддельное облако» с перезапуском помощника посреди загрузки.
- Плагин в Reaper: скрипт ReaScript ставит плагин на мастер и проверяет, что помощник запущен и привязка создана (скриптуемо, как корпус `.rpp`).
- Logic Pro и Ableton Live: ручной чек-лист (скриптовать нельзя).
- Настоящие облака: ручная проверка автором после регистрации приложений.

### D12. Средства проверки [добавлено при реализации]

- `core/internal/backuper/cloud/cloudtest` — поддельные серверы обоих облаков и их служб входа; `fakecloud` — тот же поддельный Яндекс Диск отдельной программой для проверок с настоящими помощником и плагином.
- Переменные окружения для проверок: `AUDIO_BACKUPER_DATA_DIR`, `AUDIO_BACKUPER_SECRETS=file`, `AUDIO_BACKUPER_YANDEX_API_URL`, `AUDIO_BACKUPER_GOOGLE_API_URL`, `AUDIO_BACKUPER_HELPER`, `AUDIO_BACKUPER_IDLE_EXIT_SECONDS`. Они позволяют запускать всё, не трогая настоящий каталог данных, Keychain и аккаунт.
- `tools/reaper/backuper-e2e.sh` — плагин в отдельном экземпляре Reaper; `backuper-idle.sh` — нагрузка в простое; `backuper-screens.sh` — изображения окна во всех состояниях без DAW.
- `juce-client/Tests` — прохождение звука, раскладки каналов, состояние проекта, скорость удаления экземпляра.

## Risks / Trade-offs

- **Logic не даёт плагину запускать процессы** → проверка в начале работ (задача 1.1); запасной вариант — агент пользователя из D2.
- **Нет идентификаторов OAuth** → вход через браузер нельзя проверить на настоящих облаках; поддельные серверы покрывают протокол, но не расхождения с реальностью. Ручной токен Яндекса позволяет проверить загрузку раньше.
- **Приложение Google в режиме тестирования** выдаёт доступ на 7 дней и не более чем 100 пользователям → для чужих машин нужна публикация приложения; до неё пользователь раз в неделю входит заново (состояние «нужен вход» это покрывает).
- **Секрет клиента в приложении не секрет** (настольное приложение — публичный клиент) → права минимальны (D7), PKCE для Google.
- **Только папка приложения** → нельзя писать в произвольную папку диска; принято ради минимальных прав.
- **Ableton Live и Windows не проверяются на машине автора** → сборка под Windows в CI ловит ошибки компиляции, но не поведения; остаётся ручная проверка.
- **Переименование прежней версии и загрузка новой — два шага** → при обрыве между ними в облаке останется только переименованная прежняя; новая загрузится при повторе, данные не теряются.
- **Go в сборке плагина** → в README и CI.

## Migration Plan

1. Помощник и плагин развиваются рядом с прототипом; `backuper-service/` не трогается до паритета.
2. После сквозной проверки в Reaper `backuper-service/` удаляется, README переписывается.
3. `~/.audio-backuper.json` не читается и не удаляется; в заметках к выпуску — «войдите в облако заново, старый файл можно удалить».
4. Откат — предыдущий коммит: формат проекта DAW у прототипа пустой, терять нечего.

## Open Questions

- Разрешает ли Logic Pro 11 плагину запуск отвязанного процесса и сетевые вызовы к `127.0.0.1` — задача 1.1. В процессе `auval` и в Reaper это работает; в самом Logic не проверено.
- Расходятся ли настоящие API облаков с поддельными серверами: права `disk.info` для сведений о диске, ответы при нехватке места, асинхронное переименование в Яндексе, поведение возобновляемой загрузки Google — задача 5.9.
- Keychain на macOS через системную утилиту `security`: запись доступна любой программе того же пользователя. Это защищает от других пользователей и от чтения диска, но не от программ самого пользователя; решить, достаточно ли этого, при подготовке поставки.
- Поддерживает ли Яндекс OAuth PKCE для потока с кодом устройства (в документации найдено только для кода авторизации) — уточнить при реализации; на выбор потока не влияет.
- Нужна ли в первой версии папка вне области приложения Яндекса (многие хранят музыку в корне диска) — ждёт отзывов.
