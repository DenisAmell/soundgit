## Purpose

Локальная история версий проекта DAW: фиксация состояния проекта и его аудиофайлов, просмотр истории, сравнение версий и точное восстановление любой из них без подключения к сети.

## ADDED Requirements

### Requirement: Инициализация репозитория

Команда `soundgit init` SHALL создавать локальный репозиторий в каталоге проекта и связывать его с файлом проекта.

#### Scenario: Каталог с одним файлом проекта

- **WHEN** `soundgit init` выполнена в каталоге с одним файлом `.rpp`
- **THEN** создан репозиторий, связанный с этим файлом, и команда сообщает его имя

#### Scenario: Несколько файлов проекта

- **WHEN** в каталоге несколько файлов `.rpp` и файл не указан явно
- **THEN** команда завершается ошибкой со списком найденных файлов

#### Scenario: Репозиторий уже существует

- **WHEN** `soundgit init` выполнена в каталоге с существующим репозиторием
- **THEN** команда завершается ошибкой и не изменяет существующий репозиторий

### Requirement: Фиксация версии

Команда `soundgit commit -m <сообщение>` SHALL сохранять неизменяемую версию, включающую состояние проекта и содержимое всех аудиофайлов, на которые он ссылается внутри каталога проекта, вместе с автором, временем и сообщением.

#### Scenario: Первая фиксация

- **WHEN** выполнена фиксация в новом репозитории
- **THEN** создана версия без родителя и напечатан её идентификатор

#### Scenario: Нет изменений

- **WHEN** фиксация запрошена, а проект и аудиофайлы не отличаются от последней версии
- **THEN** новая версия не создаётся и команда сообщает, что изменений нет

#### Scenario: Некорректный файл проекта

- **WHEN** файл проекта не удаётся разобрать
- **THEN** фиксация не создаётся, репозиторий не изменён, выведена причина

#### Scenario: Отсутствует аудиофайл

- **WHEN** проект ссылается на аудиофайл, которого нет на диске
- **THEN** версия создаётся, а команда выводит предупреждение с путём отсутствующего файла

#### Scenario: Аудиофайл вне каталога проекта

- **WHEN** проект ссылается на аудиофайл за пределами каталога проекта
- **THEN** версия создаётся, ссылка записана как внешняя, выведено предупреждение, что такая версия может не восстановиться на другой машине

### Requirement: Хранение без дублирования одинаковых файлов

Репозиторий SHALL хранить содержимое аудиофайла однократно, если оно совпадает между версиями или между файлами.

#### Scenario: Повторная фиксация с тем же аудио

- **WHEN** между двумя фиксациями изменён только темп проекта
- **THEN** объём репозитория увеличивается на величину, не зависящую от размера аудиофайлов

### Requirement: Состояние рабочего каталога

Команда `soundgit status` SHALL сообщать, отличается ли рабочее состояние от последней версии, перечисляя изменения проекта в терминах сущностей и изменённые, новые и отсутствующие аудиофайлы.

#### Scenario: Изменён проект

- **WHEN** после фиксации в DAW изменена громкость дорожки и проект сохранён
- **THEN** `status` показывает изменение громкости этой дорожки

#### Scenario: Нет изменений

- **WHEN** рабочее состояние совпадает с последней версией
- **THEN** `status` сообщает, что изменений нет

### Requirement: История

Команда `soundgit log` SHALL выводить версии от последней к первой с идентификатором, автором, временем и сообщением.

#### Scenario: Три версии

- **WHEN** в репозитории три версии
- **THEN** `log` выводит три записи в обратном хронологическом порядке

#### Scenario: Машиночитаемый вывод

- **WHEN** `log` вызвана с флагом `--json`
- **THEN** вывод является корректным JSON с теми же данными

### Requirement: Сравнение версий

Команда `soundgit diff [<версия A>] [<версия B>]` SHALL выводить семантические различия между двумя версиями либо между версией и рабочим состоянием.

#### Scenario: Две версии

- **WHEN** указаны два идентификатора версий
- **THEN** выведены изменения между ними в терминах дорожек, элементов, эффектов, автоматизации и темпа

#### Scenario: Без аргументов

- **WHEN** `diff` вызвана без аргументов
- **THEN** сравниваются последняя версия и рабочее состояние

#### Scenario: Неизвестная версия

- **WHEN** указан идентификатор, которого нет в репозитории
- **THEN** команда завершается ошибкой и ничего не изменяет

### Requirement: Восстановление версии

Команда `soundgit restore <версия>` SHALL приводить файл проекта и аудиофайлы в рабочем каталоге в точное соответствие указанной версии.

#### Scenario: Точное восстановление

- **WHEN** версия зафиксирована, затем проект и аудиофайлы изменены, затем выполнено `restore` этой версии
- **THEN** файл проекта побайтово совпадает с зафиксированным
- **AND** каждый аудиофайл версии побайтово совпадает с зафиксированным

#### Scenario: История не переписывается

- **WHEN** выполнено восстановление старой версии
- **THEN** все ранее созданные версии остаются в истории и доступны для восстановления

### Requirement: Защита незафиксированной работы

Перед перезаписью рабочего состояния, отличающегося от последней версии, система MUST сохранить его как страховочную версию и сообщить её идентификатор.

#### Scenario: Восстановление поверх несохранённых в истории правок

- **WHEN** рабочее состояние содержит незафиксированные изменения и выполнено `restore`
- **THEN** до перезаписи создана страховочная версия и напечатан её идентификатор
- **AND** `restore` этой страховочной версии возвращает незафиксированные изменения

#### Scenario: Сбой во время восстановления

- **WHEN** восстановление прервано до завершения
- **THEN** ни один файл не остаётся частично записанным и репозиторий остаётся целостным

### Requirement: Целостность хранилища

Система MUST проверять соответствие содержимого объекта его идентификатору при чтении и отказывать в операции при несовпадении.

#### Scenario: Повреждённый объект

- **WHEN** файл объекта в репозитории повреждён и запрошено восстановление версии, которая его использует
- **THEN** команда завершается ошибкой с идентификатором повреждённого объекта и не изменяет рабочий каталог

### Requirement: Работа без сети

Все команды локальной истории SHALL работать без сетевого подключения.

#### Scenario: Офлайн

- **WHEN** сеть недоступна
- **THEN** `init`, `commit`, `status`, `log`, `diff` и `restore` выполняются успешно
