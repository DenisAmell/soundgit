## Context

Плагин собирается CMake; помощник кладётся внутрь бандлов (`rebuild-audio-backuper`, D10). На машине автора сертификатов подписи нет (плагин подписан ad-hoc). Windows-машины нет: установщик для Windows можно проверить только в CI.

## Goals / Non-Goals

**Goals:**

- Человек без инструментов разработки ставит плагин одним установщиком и видит его в DAW.
- Обновление не требует закрывать DAW заранее и не теряет очередь.
- Каждая сборка выпуска проверена установкой, а не только компиляцией.
- Один и тот же процесс даёт подписанную сборку при наличии сертификатов и неподписанную без них.

**Non-Goals:** автообновление, Linux, AAX, получение сертификатов.

## Decisions

### D1. macOS: один `.pkg` из двух компонентов

`pkgbuild` делает по пакету на AU и VST3, `productbuild` собирает их в один установщик с выбором «для всех пользователей» (`/Library/Audio/Plug-Ins`, нужен пароль администратора) или «только для меня» (`~/Library/Audio/Plug-Ins`). Сценариев до и после установки нет.
**Причина:** `.pkg` — привычный для музыкантов способ ставить плагины; встроенные средства системы, без сторонних инструментов. `.dmg` с перетаскиванием не подходит: папки плагинов скрыты в `Library`.
**Причина отсутствия сценариев:** помощник запускается плагином по требованию, ставить в автозагрузку нечего. Работающий помощник продолжает жить со старым файлом в памяти; новый плагин попросит его уступить место по версии (`rebuild-audio-backuper`, D2).

### D2. Windows: Inno Setup

Установщик кладёт бандл в `%CommonProgramFiles%\VST3\Audio Backuper.vst3` — стандартное место VST3 — и регистрирует удаление. Перед установкой и удалением он завершает работающего помощника.
**Причина остановки помощника:** в Windows исполняемый файл занят, пока процесс работает, и заменить или удалить его нельзя. Очередь лежит на диске, помощник запустится снова при первой загрузке плагина.
**Альтернатива:** WiX/MSI — отвергнуто: для одной папки и одной записи об удалении это лишняя сложность.

### D3. Подпись — по наличию учётных данных

Сценарии сборки читают учётные данные из окружения:

| Переменная | Что включает |
|---|---|
| `MACOS_APP_IDENTITY` | подпись бандлов и помощника сертификатом Developer ID Application с защищённой средой выполнения |
| `MACOS_INSTALLER_IDENTITY` | подпись `.pkg` сертификатом Developer ID Installer |
| `MACOS_NOTARY_PROFILE` | нотаризация и прикрепление квитанции |
| `WINDOWS_SIGN_CERT`, `WINDOWS_SIGN_PASSWORD` | подпись помощника, плагина и установщика |

Без них бандлы подписаны ad-hoc, а к имени файла установщика добавляется `-unsigned`.
**Причина пометки в имени:** неподписанная сборка вызывает предупреждения системы; получатель должен понимать, что это ожидаемо, а не подмена.
Сначала подписывается помощник, затем бандл: подпись бандла запечатывает его содержимое.

### D4. Версия из одного места

Источник — `Version` в `core/internal/backuper/helper/helper.go`. CMake читает её до `project()` и ставит версией плагина; сценарии упаковки берут её у собранного помощника (`--version`). Имена: `AudioBackuper-<версия>-macOS[-unsigned].pkg`, `AudioBackuper-<версия>-Windows-x64[-unsigned].exe`.

### D5. Проверка установкой

Сценарий упаковки не заканчивается на создании файла. После сборки установщик ставится (на macOS — в домен текущего пользователя, без пароля; на Windows — тихо), и проверяется: файлы на месте, подпись бандлов цела, помощник внутри запускается и сообщает ту же версию, на macOS — `auval`. Затем выполняется удаление и проверяется, что плагин убран, а данные пользователя (каталог помощника) не тронуты.

### D6. Выпуск в CI

Workflow `backuper-release` запускается тегом `backuper-v*` или вручную. Два задания (macOS, Windows): сборка, упаковка, проверка установкой, выгрузка артефакта. По тегу артефакты прикладываются к **черновику** выпуска GitHub — публикует его человек. Идентификаторы приложений облаков и учётные данные подписи берутся из секретов репозитория; при их отсутствии сборка проходит, но вход через браузер отключён, а установщики не подписаны.
Тег выпуска должен совпадать с версией в коде, иначе сборка останавливается.

### D7. Удаление не трогает данные

Удаляются только файлы плагина. Каталог помощника (очередь, состояние, журнал) и доступ к облаку в системном хранилище остаются: переустановка продолжает с того же места. Как убрать и их — в README.

## Risks / Trade-offs

- **Нет сертификатов** → на чужом Mac неподписанный `.pkg` открывается только через «Открыть» в контекстном меню или настройки безопасности; в Windows — предупреждение SmartScreen. Описано в README; снимается только подписью.
- **Установщик Windows проверяется только в CI** → поведение на реальной машине с DAW остаётся за ручной проверкой (задача автора).
- **Работающий помощник старой версии после обновления на macOS** → заменяется при первой загрузке нового плагина; если версии равны (пересборка), остаётся прежний до своего завершения.
- **Универсальная сборка плагина вдвое дольше** → выполняется только при упаковке, обычная сборка разработчика остаётся под свою архитектуру.

## Migration Plan

Пользователей у прототипа нет. Сборка разработчика (`build.sh`) продолжает ставить плагин в домашний каталог; установщик кладёт в те же места.
