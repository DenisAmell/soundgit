# SoundGit — концепция

> Источник истины по идее проекта. Архитектура — в [architecture.md](architecture.md), этапы — в [roadmap.md](roadmap.md).
> Пометка **[решение]** — выбор, сделанный при проектировании (не требование автора); его можно оспорить и изменить.

## Формулировка в одну фразу

SoundGit — система контроля версий для проектов DAW, которая понимает проект как **структуру** (дорожки, клипы, темп, эффекты, автоматизация), а не как текст или байты, и поэтому умеет сравнивать, сливать и откатывать версии по смыслу, храня аудио без дублирования.

## Проблема

Аранжировщик, вокалист и звукорежиссёр работают над одним проектом из разных мест и в разное время. Сегодня это пересылка архивов и «проект_финал_v7_точно.rpp»:

- файл проекта нельзя осмысленно сравнить и слить: Git сравнивает строки, а одна правка громкости в `.rpp` меняет десятки строк;
- аудио копируется целиком в каждую версию;
- облачные функции производителей работают только внутри своей DAW и не дают ветвления и слияния;
- проект не открывается на другой машине из-за отсутствующих плагинов.

## Для кого

Небольшие распределённые команды (2–5 человек), работающие над одним проектом **асинхронно**. Не аудитория: живой джем в реальном времени.

## Ключевые свойства

| Свойство | Что это значит для пользователя |
|---|---|
| Синхронизация проекта | Дорожки, клипы, темп, размер, автоматизация, цепочки эффектов и аудио приезжают к коллеге одной операцией |
| История и откат | Любую зафиксированную версию можно посмотреть, сравнить и восстановить; история не переписывается |
| Слияние и конфликты | Непересекающиеся правки сливаются сами; конфликт возникает только при правке одной и той же сущности и показывается в терминах проекта («громкость дорожки Bass: у вас −6 дБ, у Ани −3 дБ») |
| Не нагружает проект | Вся работа идёт вне процесса DAW; модуль в DAW не обрабатывает звук и не делает ввода-вывода в аудиопотоке |
| Мультиплатформенность | macOS, Windows, Linux; один и тот же проект открывается на разных ОС |
| Экономное хранение | Совпадающие фрагменты аудио хранятся один раз для всех версий и участников |
| Воспроизводимое окружение | Lock-файл плагинов показывает, чего не хватает для открытия проекта |

## Что значит «standalone-плагин» **[решение]**

Плагин формата VST3/AU **не имеет доступа к проекту хоста**: он видит только аудио/MIDI своей дорожки и транспорт. Прочитать чужие дорожки, темп-карту или настройки соседних плагинов из плагина нельзя. Поэтому SoundGit устроен так:

- **ядро** — отдельный фоновый процесс рядом с DAW, работающий с **файлом проекта на диске** (`.rpp`) и папкой медиа;
- **клиент в DAW** — тонкая панель управления (плагин и отдельное приложение из одного кода), которая только показывает состояние и отправляет команды ядру;
- **мост к DAW** (позже) — небольшой скрипт самой DAW (для Reaper — ReaScript), который по команде сохраняет и перезагружает проект, чтобы пользователю не делать это руками.

Это и даёт «не грузит проект»: тяжёлая работа физически вне DAW.

## Цели

1. Полный цикл для Reaper: init → commit → push → pull → merge → разрешение конфликта → откат.
2. Формат-независимая модель проекта (IR), на которой работают diff и merge; вторая DAW (Ableton Live) подключается адаптером без изменения алгоритмов.
3. Отсутствие потери данных — главный инвариант: любая зафиксированная версия восстанавливается точно; рабочее состояние никогда не перезаписывается без страховочного снимка.
4. Офлайн-работа: все операции, кроме push/pull, работают без сети.
5. Измеримые результаты для ВКР: доля автоматических слияний против `git merge`, коэффициент дедупликации, качество слияния аудио.

## Не-цели

- Совместное редактирование в реальном времени (как Google Docs).
- Конвертация проектов между DAW (IR общий для алгоритмов, но проект Reaper остаётся проектом Reaper).
- Распространение бинарников коммерческих плагинов (только манифест-ссылка).
- Собственная DAW, обработка звука в плагине.
- Версионирование содержимого аудиофайлов на уровне сигнала в основном продукте — это исследовательское направление ВКР (см. roadmap, трек R).

## Анти-цели (провал, даже если «технически работает»)

- Слияние, которое молча теряет чужую правку или выдаёт проект, не открывающийся в DAW.
- Щелчки, дропауты или подвисания DAW из-за SoundGit.
- Парсер, который при записи теряет поля `.rpp`, которых не понимает.

## Контрольный сценарий (из НИР)

Два пользователя клонируют общий проект. Первый меняет темп и добавляет дорожку; второй параллельно редактирует аранжировку другой дорожки. Платформа сливает правки автоматически. Затем оба правят одну дорожку — платформа показывает конфликт и средства разрешения. DI обоих хранятся в облаке без дублей; недостающие плагины определяются по lock-файлу.

## Словарь

| Термин | Значение |
|---|---|
| IR | Промежуточное представление: нормализованная модель проекта, не зависящая от формата DAW |
| Адаптер DAW | Пара «парсер + писатель» между форматом DAW и IR |
| Снимок (snapshot) | Неизменяемое состояние проекта: IR + манифесты ассетов |
| Коммит | Снимок + родители + автор + время + сообщение |
| Ассет | Аудио- или иной медиафайл проекта |
| Чанк | Блок переменного размера, на которые режется ассет (FastCDC), адресуется хешем BLAKE3 |
| Манифест ассета | Упорядоченный список чанков, из которых собирается файл |
| Ядро (core) | Библиотека и исполняемый файл `soundgit`: CLI и фоновый агент |
| Агент (daemon) | Ядро в режиме фонового процесса с локальным API |
| Клиент | JUCE-панель: плагин и отдельное приложение |
| Мост | Скрипт внутри DAW для сохранения/перезагрузки проекта по команде агента |

## Происхождение

Магистерская диссертация (МАИ, каф. 806) «Разработка платформы контроля версий и организации совместной работы над проектами цифровых звуковых рабочих станций». Научная новизна, которую должен поддержать прототип: формат-независимое IR с формальными diff/merge; критерий конфликта для аудио в плоскости время × частота; трёхстороннее слияние сигналов `x_m = Φ⁻¹(Φ(x_A) + Φ(x_B) − Φ(x_0))`; подбор content-defined chunking для аудио и описание изменений с помощью LLM и аудиоэмбеддингов.
