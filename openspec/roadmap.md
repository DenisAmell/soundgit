# SoundGit — поэтапный план

> Каждый этап оформляется отдельным изменением OpenSpec (`openspec/changes/<имя>`) в момент начала работ; здесь — порядок, результат и критерий готовности. Обновляйте статус при архивации изменения.

Принцип порядка: **сначала ядро без сети и без UI**, проверяемое из командной строки; сервер и интерфейс — когда есть что синхронизировать и показывать. Каждый этап заканчивается работающей демонстрацией.

## Этап 0. Каркас

- Структура монорепозитория (см. architecture.md §10), Go-модуль `core/`.
- CI: сборка и тесты на macOS, Windows, Linux.
- Корпус тестовых проектов `testdata/`: минимальные `.rpp` на каждую сущность + 3–5 реальных проектов.

**Готово, когда:** `go test ./...` зелёный на трёх ОС; корпус лежит в репозитории.

## Этап 1. Локальное ядро версий

Парсер и писатель `.rpp` без потерь, IR, объектное хранилище, CLI: `init`, `status`, `commit`, `log`, `diff`, `restore`. Аудио пока хранится целыми файлами по хешу.

**Готово, когда:** любой проект корпуса проходит круг «разбор → запись» побайтово; после `commit` → правок → `restore` проект идентичен зафиксированному; `diff` между двумя версиями печатает изменения в терминах дорожек/элементов.
**Для ВКР:** задачи 1–2 (анализ формата, IR, формальная модель diff).

## Этап 2. Хранилище аудио с дедупликацией

FastCDC + BLAKE3, манифесты ассетов, материализация файлов из чанков, сборщик мусора, сбор внешних файлов в `media/`.

**Готово, когда:** повторная фиксация проекта с частично изменённым аудио добавляет в хранилище только изменённые чанки; восстановленные файлы побайтово совпадают.
**Для ВКР:** задача 4 — эксперимент «FastCDC против фиксированных блоков и целых файлов», подбор параметров.

## Этап 3. Ветки и семантическое слияние

Ветки, поиск общего предка, трёхстороннее слияние IR по правилам architecture.md §4, структурные конфликты, разрешение из CLI (`merge`, `conflicts`, `resolve --ours/--theirs/--base/--both`), семантическая валидация.

**Готово, когда:** контрольный сценарий НИР воспроизводится локально на двух клонах; набор property-тестов подтверждает: слияние без конфликтов коммутативно, слияние с неизменённой стороной тождественно, результат всегда открывается писателем.
**Для ВКР:** задача 3 и метрика «доля автоматических слияний и ложных конфликтов против `git merge` (diff3)».

## Этап 4. Сервер и синхронизация

NestJS + PostgreSQL + MinIO в Docker Compose. Регистрация/вход (JWT), проекты и участники, загрузка объектов по presigned-URL, пакетная проверка наличия хешей, атомарное обновление веток. В ядре: `clone`, `push`, `pull`, `remote`.

**Готово, когда:** два пользователя на разных машинах проходят контрольный сценарий через сервер; повторный push не передаёт уже имеющиеся чанки; гонка двух push в одну ветку не теряет ни один коммит.

## Этап 5. Агент, клиент JUCE, мост Reaper

Режим `soundgit daemon` с локальным API и событиями; перенос резервного копирования из `backuper-service` в агент и удаление Node-сервиса; клиент JUCE перенацеливается на агент: история, diff, фиксация, синхронизация, экран конфликтов; ReaScript-мост «сохранить / перезагрузить»; локальные автоснимки при сохранении.

**Готово, когда:** весь контрольный сценарий проходится мышью из панели в Reaper без терминала; во время записи с открытой панелью нет дропаутов (замер нагрузки CPU и аудиопотока).

## Этап 6. Совместная работа

`soundgit.lock` и проверка плагинов при восстановлении; реестр плагинов на сервере (свободные — с артефактами, коммерческие — манифест-ссылка); рекомендательные блокировки ассетов; уведомления о новых коммитах коллег.

**Готово, когда:** проект, открытый на «чистой» машине, показывает точный список недостающих плагинов и доустанавливает свободные.

## Этап 7. Упаковка

Установщики для трёх ОС, подпись и нотаризация (macOS), встраивание ядра в комплект клиента, автозапуск агента, обновления.

## Этап 8. Ableton Live

Адаптер `.als` (gzip + XML) ↔ IR. Diff/merge не меняются — это и есть проверка тезиса о формат-независимости.

## Этап 9. Logic Pro на уровне «пакет»

Адаптер уровня 1 (architecture.md §2.5): версионирование пакета `.logicx` целиком, сравнение по `MetaData.plist`, чужая версия при конфликте — как «Альтернатива» в пакете. Автослияния нет. Рассматривался как первый этап и отложен 2026-11-15: формат `ProjectData` закрыт.

**Готово, когда:** проект Logic фиксируется, восстанавливается побайтово и синхронизируется; параллельные правки двух участников не теряются и обе версии открываются в Logic.

## Трек R. Исследования ВКР (Python, параллельно)

| Шаг | Содержание | Данные / метрика |
|---|---|---|
| R1 | Генератор синтетических правок (громкость, фейды, EQ, вырезание/вставка, наложения) с эталоном `B(A(x₀))` | MUSDB18, Slakh2100 |
| R2 | Слияние сигналов через Φ; критерий конфликта «время × частота» | SI-SDR относительно эталона |
| R3 | Детектор изменений и классификатор операций на аудиоэмбеддингах (LAION-CLAP) | IoU |
| R4 | Автоматическое описание изменений: структурный diff IR → текст с помощью LLM | Ручная выборочная проверка |
| R5 | Сводные эксперименты: дедупликация, доля автослияний | Таблицы для диссертации |

Связь с продуктом: R4 подключается к `commit` как подсказка сообщения; R2 — как необязательная стратегия разрешения конфликта ассетов. Ни одно не блокирует этапы 1–6.
