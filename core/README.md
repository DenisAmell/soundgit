# SoundGit core

Ядро SoundGit: разбор проектов Reaper в модель (IR), сравнение версий по смыслу и локальная история.
Один исполняемый файл `soundgit`, без сети и без фоновых процессов.

## Сборка и тесты

Нужен Go 1.26 или новее (этого требуют зависимости).

```bash
cd core
go build -o soundgit ./cmd/soundgit
go test ./...
```

Проверка парсера случайным вводом и замер скорости:

```bash
go test ./internal/rpp -run '^$' -fuzz FuzzParse -fuzztime 30s
go test ./internal/rpp -run '^$' -bench .
```

## Работа

```bash
cd путь/к/проекту        # папка с файлом .rpp
soundgit init            # начать вести историю
soundgit commit -m "Первая версия"
soundgit status          # что изменилось после последней версии
soundgit log             # список версий
soundgit diff HEAD~1 HEAD
soundgit restore HEAD~1  # вернуть проект к версии
```

- Перед фиксацией сохраните проект в Reaper: ядро читает файл с диска.
- После `restore` переоткройте проект в Reaper.
- `restore` не меняет историю. Если в папке была незафиксированная работа, она сохраняется как страховочная
  версия; её идентификатор печатается, список — `soundgit log --safety`.
- Версия — это `HEAD`, `HEAD~N`, идентификатор или его первые символы (от четырёх).
- `status`, `log`, `diff` умеют `--json`.

## Что хранится

Каталог `.soundgit/` в папке проекта: объекты с адресацией по содержимому (BLAKE3), ссылка на последнюю
версию, страховочные версии. В версию входят файл проекта и аудиофайлы, на которые он ссылается внутри папки
проекта. Файл вне папки проекта записывается только как ссылка с контрольной суммой — с предупреждением.

## Устройство

| Пакет | Назначение |
|---|---|
| `internal/rpp` | Дерево `.rpp`: чтение и запись без потерь |
| `internal/ir` | Модель проекта, каноническая сериализация |
| `internal/adapters/reaper` | `.rpp` ↔ модель; соответствие полей — в `MAPPING.md` |
| `internal/diff` | Сравнение двух моделей |
| `internal/store` | Объекты на диске с проверкой целостности |
| `internal/repo` | Версии, рабочий каталог, восстановление |
| `internal/cli` | Команды |

## Проверка в Reaper

Автоматически проверено на Reaper 7.86: файлы, сохранённые Reaper, читаются и записываются побайтово, а файл,
записанный из изменённой модели, Reaper открывает с теми же значениями (см. `tools/reaper/README.md`).

На слух не проверялось. Шаги:

1. Открыть в Reaper рабочий проект, сохранить.
2. `soundgit init`, `soundgit commit -m v1`.
3. Изменить темп и громкость дорожки, сохранить; `soundgit status` должен показать именно эти изменения.
4. `soundgit commit -m v2`, затем `soundgit restore HEAD~1`.
5. Переоткрыть проект: он должен открыться без предупреждений и звучать как на шаге 1.
